The rule that must never break

    

      You just saw something easy to miss: cutting the pile made it faster, and
      the answer never changed. That is not luck. It is the one thing this whole trick depends on —
      and in Bend you can write it down as a rule the computer will not let anyone break.
    


    

      The rule
      However the pile is cut, the fast answer must be exactly the answer you would get by
      reading the documents one at a time. For every pile. Every time.
    


    

      
      

        

          
LAWS.bend
🔒 a human owns this

Why it failed, in plain numbers

        

          Take a lopsided pile: one document scoring 90 on the left, and three
          documents scoring 10 each on the right.
        

        

          

            
The AI's fast code

            
left avg = 90
right avg = 10
(90 + 10) ÷ 2

            
50

          

          

            
Reading one at a time

            
90 + 10 + 10 + 10 = 120
 
120 ÷ 4 documents

            
30

          

        

        

          The average of two averages is not the average. The code says this pile scores 50
          when it scores 30. It only goes wrong when the two halves hold different numbers of
          documents — which is most of the time, and exactly the case a hand-written test tends to miss.
        

      

    

  










  

    
Putting the two together

    
Why this combination is interesting

    

      An AI agent can write code faster than anyone can read it. The awkward question is how you
      know the code is right. Bend's answer is not “trust the model” or “write more tests” —
      it is to make certain mistakes impossible to merge.
    


    

      

        
01
A human writes the rules

        
Short, plain, reviewable. Four lines in the demo above. The AI agent is not allowed to edit them.

      

      

        
02
The AI writes the code

        
And a proof that the code obeys every rule. Both get rewritten as often as the agent likes.

      

      

        
03
The checker runs

        
About a fifth of a second. Fast enough for an agent to re-check after every single edit, not once a night.

      

      

        
04
No proof, no merge

        
A change that breaks a rule cannot get in. One that keeps them runs in parallel on every core you own.

      

    


    

      Notice what did not happen in demo 2. Nobody wrote a test for the lopsided pile.
      Nobody reviewed the AI's code line by line. The human wrote down one sentence about what must
      always be true, and that sentence was still doing its job two rewrites later.
    


    

      
Where the guarantee stops

      
    
        
  • Bend proves the rules you wrote, and nothing else. A property nobody thought to
          write down is not protected. Our own trial hit this: a rule that was too weak passed
          happily while the code was still wrong.
    • 
        
  • It does not make AI-written code bug-free. It makes one specific class of mistake
          — breaking a stated rule — impossible to merge. That is a narrower and more useful claim.
    • 
        
  • Only pure computation is practically provable. Code that touches the network,
          the clock or the filesystem sits outside the proof.
    • 
        
  • The speed-ups are bounded by your hardware, and by how evenly the work splits.
          You saw both ceilings in demo 1.
    • 
        
  • Bend 2 is new — released 17 September 2026. Its own README says
          “BEND IS YOUNG. EXPECT BUGS.” This page is an explanation, not a recommendation to ship on it.

For the technically curious

    
What Bend actually is

    
Now that the pictures are in your head, the words are easy.

    

      
Category
A general-purpose programming language with Python-shaped syntax

      
Parallelism
The a b = f(x) g(y) parallel call. Fork-join across cores or GPU. No threads, no locks, no kernels

      
Why that is safe
The language is pure and affine — a value is used at most once — so two halves cannot interfere

      
Laws & proofs
The type checker is the proof checker, as in Lean or Rocq. A proposition is a type; a proof is a definition of that type

      
The gate
bend PROOF.bend fails while any law is unproven and prints “All terms check.” when they all hold

      
Speed of the check
Around 0.2 s on a small codebase in our trial; the project claims a second at most. Lean and Rocq take minutes

      
Targets
C, CUDA, Metal and JavaScript. The JS target runs sequentially

      
Status
Released 17 Sep 2026 by Victor Taelin / Higher Order Company. Apache-2.0. Early

    

    

      Every Bend snippet on this page uses real syntax from the language guide: law /
      for / {a == b : T} for rules, {==} for a proof step that closes
      by computation, a b = f(x) g(y) for a parallel call and f!(x) to run it
      on the GPU. The 64-document run is a simulation in this page, not the compiler — the timings model
      Bend's fork-join scheduler on eight cores, ignoring join overhead, so real speed-ups land a little
      below the ideal shown here.
